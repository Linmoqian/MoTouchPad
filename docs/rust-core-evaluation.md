# Rust 共享核心评估

## 当前状态

2026-10-14 已完成独立 Rust 原型、C ABI、Swift 调用适配器、动作对照与三轮基准。
18:23–18:24（北京时间）完成较低负载下的三轮复测。
当前决定：保留原型，暂不迁移应用核心。复测中 Rust 原生路径更快，但完整 Swift
适配路径比 Swift 原生慢约 33%，每步骤增加约 53 ns，没有显示宿主路径收益。

Rust 的 5 项测试、Clippy、现有 Swift 的 30 项测试和两套 Release 构建均通过。
跨语言每轮核对 569 个共享步骤、23,806 个固定种子及阈值边界步骤、18 个协议
样例与全部 15 个命名命令。三轮四条业务路径的跨进程校验和一致。

## 原型范围

Rust 实现 protocol v1 编解码、增量流解析与现有 macOS 手势核心默认配置。输入为
原始触点快照，输出为移动、点击、拖移、二维滚动和全部 15 个命名命令。C ABI
使用独立句柄与调用者预分配动作缓冲。智能缩放配置可切换，其他自定义阈值尚未
导出，Windows 的平台手势契约和 Android/iOS 绑定尚未评估。

现有 Swift 核心仅新增 SwiftPM library product，方便独立工具引用。应用主链继续
使用现有原生核心，Rust 无 CGEvent、TCP、DriverKit 或 UI 依赖。

## 验证与测量方法

共享固定轨迹包含 37 个场景、569 个步骤，逐步比较动作类型、按键、命令、重复
次数、位移（绝对容差 1e-6）及下一次计时截止时间（1e-9 秒）。另有固定种子压力
轨迹与浮点阈值相邻值测试，覆盖取消、UP、ID 变更、升级和重置。两个 codec 验证
18 个协议黄金样例；合法样例测试所有分片位置与合帧。

Release 基准串行测试 Swift 原生、Rust 原生、Swift→Rust 固定动作缓冲、Swift→Rust
转换回 `[GestureAction]` 四条路径。每步也查询计时截止时间，跨语言路径计入两次
C 调用。空 C 恒等函数单独测量，仅估算空调用加循环成本。相同输入与校验和用于
防止回放遗漏，四条业务路径的校验和必须跨进程一致。

默认三轮，每轮预热八次，每个采样块完整回放轨迹 64 次，每条路径采集 51 个块。
报告取三轮中位数的中位数。P95/P99 是采样块平均 ns/步骤的分布，采用最近秩
分位数；它们不是单帧尾延迟。数据包含解码、状态机、结果处理、截止时间查询，
不含文件载入、协议编码、计时任务调度、网络、线程派发或系统输入。

## 环境记录

Apple M4 / arm64，macOS 26.6（25G72），Swift 6.3.1，Rust 1.95.0。
Rust 使用 release + thin LTO + 一个 codegen unit；Swift 使用 SwiftPM release。
首次测量准备阶段主机一分钟负载 61.7，内存压缩页占用约 5.5 GiB，同时存在其他
项目的编译进程。工程师暂停其他编译后继续测试，但测试期间仍记录到约 53 至 123
的一分钟负载。内存压缩占用本身不能证明正在发生内存压力；后续查询显示系统可用
内存比例为 46%。等待还包括工具启动与 Cargo package-cache 锁，尚未确定各项
等待的占比。该环境不满足稳定延迟评估条件，不能把构建等待归因于手势算子。

## 首次高负载实测

下表单位为 µs/步骤，采用三轮对应统计量的中位数。P95/P99 为块平均耗时分布。

| 路径 | 中位数 | P95 块平均 | P99 块平均 | 各轮中位数 |
|---|---:|---:|---:|---|
| Swift 原生 | 9.173 | 28.287 | 42.101 | 7.287 / 9.173 / 13.860 |
| Rust 原生 | 2.701 | 17.329 | 28.468 | 2.377 / 2.701 / 5.925 |
| Swift→Rust 固定缓冲 | 9.385 | 35.620 | 105.350 | 7.834 / 9.385 / 21.556 |
| Swift→Rust 完整适配 | 16.332 | 51.421 | 53.029 | 9.010 / 25.786 / 16.332 |
| 空 C 调用加循环 | 0.0586 | 0.1477 | 0.2184 | 0.0532 / 0.0637 / 0.0586 |

完整适配路径的汇总中位数比 Swift 高约 78%，三轮单独比较也都更慢。Rust 原生
优势未转化为本次宿主路径的优势。两路径相减包含 Swift 包装、结果处理、循环及
不同时段的调度差异，不能将差值全部视为纯 ABI 成本。

独立冒烟采样（每块回放一次、仅 1–3 个块）曾得到 Rust 原生约 0.090 µs、Swift
约 0.358 µs、完整适配约 0.215 µs。它与正式采样差距明显，且原始缓冲路径有时
比完整适配更慢，进一步说明样本环境不稳定。冒烟结果不用于性能排序或迁移决策。

Swift 的 Float.pi 位表示为 `0x40490fda`，Rust 默认常量为相邻的向上舍入值。
原型显式采用 Swift 表示，并用相邻浮点阈值轨迹核对离散动作，避免临界判定差异。

参数、轨迹和实现保持一致，重新检查构建产物后串行完成三轮。测试前后一分钟负载
分别为 3.15 和 3.62；这是两个时点的系统观察，未连续采集 CPU 利用率。
Rust 5 项测试与 Release 构建通过，Swift Release 构建通过；测量结束后重新运行
现有 Swift 30 项测试，全部通过。三轮均通过 569 个
共享步骤、23,806 个压力及边界步骤、18 个协议样例和全部 15 个命令的动作核对，
四条业务路径跨进程校验和一致。

下表单位为 ns/步骤，P95/P99 仍为采样块平均耗时分布。

| 路径 | 中位数 | P95 块平均 | P99 块平均 | 各轮中位数 |
|---|---:|---:|---:|---|
| Swift 原生 | 159.155 | 165.474 | 178.676 | 159.155 / 163.048 / 159.098 |
| Rust 原生 | 51.714 | 62.794 | 66.691 | 51.714 / 60.312 / 45.259 |
| Swift→Rust 固定缓冲 | 195.038 | 199.957 | 201.976 | 195.038 / 195.636 / 194.548 |
| Swift→Rust 完整适配 | 212.139 | 218.750 | 225.772 | 213.020 / 211.257 / 212.139 |
| 空 C 调用加循环 | 0.732 | 0.761 | 0.766 | 0.788 / 0.732 / 0.731 |

本次完整适配路径三轮均比 Swift 原生慢，汇总中位数高约 33.3%；固定缓冲路径
高约 22.5%。Rust 原生耗时低约 67.5%，但不包含 Swift 包装和完整结果转换。
Swift 三条业务路径的各轮中位数明显接近，Rust 原生仍有约 45–60 ns 的轮间差异。
首次高负载数据保留为历史记录，不用于当前性能排序。

空调用数据是优化构建中的空函数与循环测量，不能代表携带真实输入、访问状态和
转换输出的调用成本。完整适配已计入现有包装及结果消费；编译器仍可能优化临时
数组和校验和处理，结果仅代表当前基准实现。它不能推导实际 TCP、UI 或 CGEvent
延迟，也不能将路径差值全部解释为纯 ABI 开销。

## 复现

```sh
bash tools/RustCoreComparison/run.sh 64 51
bash tools/RustCoreComparison/run.sh --skip-build 64 51
python3 tools/RustCoreComparison/summarize.py
cd mac-app && swift build && swift test
```

原始数据位于 `tools/RustCoreComparison/results/`，默认忽略，当前六个 JSON 文件
对应较低负载复测；再次执行会覆盖这些文件。首次测量复用已通过构建的产物，
复测使用包含构建的命令。复用选项不会检查源码是否更新。
后续修改源码时应运行包含构建的命令。Rust 原始采样数组按数值排序，Swift 保留
采样顺序；统计使用同一最近秩规则。

本次较低负载复测支持暂缓迁移的判断。单台 M4 结果不能替代 Intel
Mac、Windows、移动端调用成本或实际 Wi-Fi 延迟验证。

## 迁移判断准则

正确性通过后，以 Swift→Rust 的完整适配路径判断宿主实际 CPU 收益。Rust 的固定
容量结构和 Swift 现有动态数组不同，测量反映实现及调用路径的共同差异，不能把
差异全部归因于语言。共享手势实现可能减少跨端维护成本，但还需要导出配置、完善
平台契约、验证其他平台绑定与构建方式。

若 CPU 节省仅为亚微秒级，它相对于 120 Hz 输入的约 8.33 ms 周期很小。只有在
实机分析确认此核心构成瓶颈，或共享维护收益明确时，才值得推进正式迁移。
